# Deployment guide

## Boundary

This is the authoritative production startup, update, verification, backup, restore, and rollback guide for `all-Mail`.

- Use [`RUNBOOK.md`](./RUNBOOK.md) for troubleshooting and recovery.
- Use [`ENVIRONMENT.md`](./ENVIRONMENT.md) for variable, secret, volume, and network ownership.
- Use [`GO-MIGRATION.md`](./GO-MIGRATION.md) for route and schema compatibility.
- Use [`../CLOUDFLARE-DEPLOY.md`](../CLOUDFLARE-DEPLOY.md) for Cloudflare Email Worker ingress.

## Supported topology

Docker Compose is the supported production topology. The six long-running services are exactly:

```text
app
go-business-api
worker-forwarding
worker-retention
postgres
redis
```

Initialization is a temporary `app init` container launched by `./scripts/compose-up.sh`; it is not a Compose service.

```text
client / reverse proxy
        |
        v
app: public Go gateway + React SPA
        |
        v
go-business-api: private Go business routes
        |                     |
        v                     v
     postgres               redis

worker-forwarding ---- postgres + provider egress
worker-retention ----- postgres
```

Only `app` is host-published. The public gateway has no PostgreSQL, Redis, JWT, encryption, OAuth, ingress-signing, provider, or bootstrap credential.

## Network boundaries

Production uses five explicit networks:

- `public-network`: `app` only; accepts the host-published listener.
- `app-network`: internal transport between `app` and `go-business-api`.
- `provider-network`: outbound provider access for `go-business-api` and `worker-forwarding`.
- `database-network`: internal PostgreSQL access for the private API and workers.
- `cache-network`: internal Redis access for `go-business-api` only.

`app` is not attached to `database-network`, `cache-network`, or `provider-network`. PostgreSQL and Redis are neither host-published nor reachable from the public gateway network.

## Prepare the environment

```bash
cp .env.example .env
openssl rand -hex 24
```

Set the generated value as `POSTGRES_PASSWORD`. Redis authentication, JWT signing, and application encryption secrets are generated by the temporary initializer and persisted in managed volumes; do not add a Redis password to `.env`.

One-time administrator inputs are optional:

```env
ADMIN_USERNAME=admin
ADMIN_PASSWORD=
```

Leave `ADMIN_PASSWORD` blank to generate a strong temporary password. Remove any populated one-shot secret from `.env` after successful initialization.

For a trusted reverse proxy or tunnel, list only directly connected peers:

```env
TRUSTED_PROXY_CIDRS=<direct-peer-cidrs>
```

Never trust `0.0.0.0/0` or `::/0`.

## Start

```bash
docker compose config --quiet
./scripts/compose-up.sh
docker compose ps -a
```

For a non-default environment file:

```bash
ALL_MAIL_ENV_FILE=/path/to/all-mail.env ./scripts/compose-up.sh
```

The helper performs this sequence:

1. require the selected environment file;
2. start and wait for `postgres`;
3. build the shared Go image;
4. resolve `runtime_secrets_data`, `bootstrap_admin_data`, `forwarding_runtime_data`, `go_business_runtime_data`, `redis_runtime_data`, and `database_runtime_data`;
5. run a temporary privileged `app init` container;
6. adopt or migrate schema history;
7. initialize or reuse JWT, encryption, and Redis authentication secrets;
8. migrate an old `bootstrap-admin.env` into the isolated bootstrap volume when upgrading;
9. export least-privilege read-only secret files;
10. start and wait for all six long-running services.

## Secret ownership

The initializer-only master state remains on `runtime_secrets_data` at:

```text
/var/lib/all-mail-state/runtime-secrets.env
```

It contains `JWT_SECRET`, `ENCRYPTION_KEY`, and `REDIS_PASSWORD`. No long-running service mounts that volume.

The private API receives only:

```text
JWT_SECRET_FILE=/var/lib/all-mail-secrets/jwt-secret
ENCRYPTION_KEY_FILE=/var/lib/all-mail-encryption/encryption-key
REDIS_PASSWORD_FILE=/var/lib/all-mail-redis/redis-password
BOOTSTRAP_ADMIN_SECRET_FILE=/var/lib/all-mail/bootstrap-admin.env
```

`bootstrap_admin_data` is writable only by the initializer and `go-business-api`, because successful forced password rotation removes the one-time plaintext credential. The sibling `/var/lib/all-mail/runtime-secrets.env` visible to the private API is a non-secret reference manifest, not the master secret bundle.

## Verify service, network, and secret ownership

```bash
for service in \
  app go-business-api worker-forwarding worker-retention postgres redis; do
  docker compose ps --services --filter status=running | grep -qx "$service"
done

docker compose port app 3000
! docker compose port go-business-api 3200
! docker compose port postgres 5432
! docker compose port redis 6379
```

```bash
docker compose exec -T app sh -lc '
  test -z "${DATABASE_URL:-}"
  test -z "${REDIS_URL:-}"
  test -z "${JWT_SECRET_FILE:-}"
  test -z "${ENCRYPTION_KEY_FILE:-}"
  test -z "${REDIS_PASSWORD_FILE:-}"
'

docker compose exec -T go-business-api sh -lc '
  test -r /var/lib/all-mail-secrets/jwt-secret
  test -r /var/lib/all-mail-encryption/encryption-key
  test -r /var/lib/all-mail-redis/redis-password
  test ! -e /var/lib/all-mail-state
  ! grep -Eq "^(JWT_SECRET|ENCRYPTION_KEY|REDIS_PASSWORD)=" /var/lib/all-mail/runtime-secrets.env
'
```

Unauthenticated Redis access must fail; authenticated health remains internal:

```bash
! docker compose exec -T redis redis-cli -p 6379 ping
docker compose exec -T redis sh -lc '
  REDISCLI_AUTH="$(cat /run/all-mail-secrets/redis-password)" redis-cli -p 6379 ping
'
```

## First login

Retrieve the one-time administrator credential only from the private API container:

```bash
docker compose exec go-business-api sh -lc \
  "grep '^ADMIN_USERNAME=' /var/lib/all-mail/bootstrap-admin.env && \
   grep '^ADMIN_PASSWORD=' /var/lib/all-mail/bootstrap-admin.env"
```

Log in through `app`, change the password, then verify plaintext retirement:

```bash
docker compose exec -T go-business-api sh -lc \
  'test ! -e /var/lib/all-mail/bootstrap-admin.env'
```

The browser never stores or prefills portal-user passwords. Portal links may contain only the username.

## Health and readiness

```bash
curl http://127.0.0.1:3002/health
curl http://127.0.0.1:3002/livez
curl --fail http://127.0.0.1:3002/readyz

docker compose exec -T app allmail doctor api
docker compose exec -T go-business-api allmail doctor business-api
docker compose exec -T worker-forwarding allmail doctor worker forwarding
docker compose exec -T worker-retention allmail doctor worker retention
```

Public readiness requires the built SPA and private `go-business-api` readiness. The private probe performs authenticated PostgreSQL and Redis checks. Worker doctors verify process identity, heartbeat freshness, current run state, and last error.

## Upgrade

Back up PostgreSQL, `.env`, the exact application revision, and all matching secret volumes. Stop the old stack before starting the new revision.

```bash
docker compose down --remove-orphans
git switch <target-tag-or-commit>
./scripts/compose-up.sh
```

On the first upgrade to the isolated layout, the initializer moves a historical bootstrap credential from the preserved physical runtime volume into `bootstrap_admin_data`, rejects conflicts, and removes the old plaintext copy. It also creates a new Redis password and exports it to `redis_runtime_data` without rotating JWT or encryption keys.

## Backup and restore

Treat these as one backup unit:

- PostgreSQL;
- `.env` and the exact application revision;
- `runtime_secrets_data`;
- `bootstrap_admin_data` while a one-time credential exists;
- `forwarding_runtime_data`;
- `go_business_runtime_data`;
- `redis_runtime_data`;
- `redis_data` when OAuth, replay, lockout, or rate-limit continuity matters.

Restore every matching component before running `./scripts/compose-up.sh`. Never use `docker compose down -v` unless permanent data destruction is intended.

## Rollback

Rollback is revision based. Stop the complete revision, deploy only a version that explicitly supports the current schema and secret layout, or restore the matching PostgreSQL and volume backup first. Never run two revisions against the same database or persisted secret state.

## Database least privilege

`POSTGRES_USER` is an initializer-only owner. Startup provisions `allmail_api`, `allmail_forwarding`, and `allmail_retention`, writes role-specific URLs to `database_runtime_data`, and mounts only the matching read-only file into each long-running process. `bash scripts/security-boundary-docker-smoke.sh` verifies role attributes and representative allow/deny table privileges.
